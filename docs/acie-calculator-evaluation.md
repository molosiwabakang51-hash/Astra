# Actual Qwen3 assisted arithmetic diagnostic

Twelve predefined public tasks: eight supported arithmetic problems and four unsuitable or ambiguous requests. Compile the exact production Kotlin calculator and incomplete-response policy into a host JVM bridge (not a duplicate Python calculator). Each actual Qwen plan uses the production planning prompt, direct profile, cap 128, fresh uncached native context. Completed plans go to the production parser. Every accepted plan triggers a separate synthesis with the actual production synthesis prompt and direct diagnostic cap 768. Strict numeric accuracy is measured against evaluator-only expected values; wrong expression values cannot earn synthesis credit, even if the model later guesses the right answer. Record unsuitable rejection and explicit NONE separately, plus incomplete plans, timing and token counts. Rejection due to incomplete generation is not proof of correct tool selection. Synthesis verbosity remains ungraded for substantive correctness but gets no strict credit. No raw model replies, plans, or internal reasoning traces are exported. The fixed synthetic questions are public developer-authored diagnostics, not independent held-out tasks; equivalent expression values do not prove semantic fidelity. Host JVM/CPU server differs from Android JNI and default handset policies. No production changes or score claim. CI relies on the runner's installed Kotlin compiler; if unavailable the job fails before inference. ACIE-078/079/080/082/083 remain open until actual evidence.
